# 設計：解き方の詳細と方法を選ぶ条件

ここに書く条件の数値（「12駅以下」「幅8以下」など）は、どれも計測して決めたものです。計測の中身は [BENCHMARKS.md](BENCHMARKS.md)、そう決めた経緯は [HISTORY.md](HISTORY.md) にあります。

## 1. 問題の整理

- 駅＝頂点、路線＝重み付きの無向辺。求めるのは、頂点を重複しない最長の「経路」または「閉路（ループ）」です。
- 最長経路問題は NP 困難です。全ての入力で速く解く方法は知られていないので、「入力の形に応じて、その形に強い厳密な方法を使う」方針を取ります。
- 出力の規定（駅IDを CRLF 区切りで出す）は崩しません。統計やエラーは標準エラーにだけ出します。

## 2. 分解：ブロックとブロックカット木

1. 連結成分ごとに解き、一番長い答えを採用します。
2. 各成分を**ブロック**（2重連結成分＝1駅を取り除いても切れない部分）に分けます。ブロックどうしは関節点（そこを取ると切れる駅）でつながり、木構造（ブロックカット木）になります。
3. 経路は関節点を通ってブロックをまたぎますが、1つのブロックに入ってから出るまでは、そのブロックの中だけを通ります。そこで、ブロックを葉の側から順に解き、関節点ごとに「そこから下の部分木へ入って稼げる最長距離 `down(a)`」を求めておきます。
4. 上のブロックを解くときは、`down(a)` を関節点 a の「端のおまけ」として扱います。経路が a で終わるなら、a の下へ続けて `down(a)` を足せる、という意味です。こうすると、大きいブロックでも関節点の数に関係なく、次の3つを求めるだけで済みます。
   - (1) そのブロックが一番上になる経路（両端のおまけ込み）
   - (2) そのブロックの中のループ
   - (3) 親の関節点から入る経路（上のブロックに渡す値。ここは常に厳密に求めます）
5. 答えの経路の駅の並びは、値が確定した後に1回だけ組み立てます。

## 3. ブロックごとの方法の選び方

| 条件 | 方法 | ファイル |
| --- | --- | --- |
| ブロックがループだけ（辺の数＝駅の数） | 公式：2駅の間の経路は2つの弧のどちらか | `bitdp.hpp` |
| 12駅以下、かつ辺が「駅の数＋8」以下 | 全経路の列挙（10万手を超えたらビットDPへ） | `bitdp.hpp` |
| 12駅以下（上以外） | ビットDP | `bitdp.hpp` |
| 13駅以上で「細い」（幅8以下、または辺が駅の数の2倍以下で幅14以下） | フロンティアDP | `frontier.hpp` |
| 上のどれでもない（400駅以下・辺2万本以下） | LP分枝カット法 | `lp_bnc.hpp` |
| それ以外、または上の方法が途中で諦めたとき | 分枝限定法 | `search.hpp` |

上の方法はどれも厳密です。フロンティアDPとLP分枝カット法は、状態数・ノード数・数値計算の検証のどれかが限度を超えると「諦めた」と返し、分枝限定法に切り替えます。諦めても答えの正しさは変わらず、時間だけが変わります。

## 4. 各方法の中身

### 4.1 小さいブロック

- **ループの公式**：駅を輪の順に並べると、2駅の間の経路は時計回りか反時計回りの2通りだけです。
- **全経路の列挙**：辺の少ない小さいブロックは、単純経路の数が少ないので深さ優先で全部たどります。ループは一番小さい番号の駅から一方向にだけ数えます。
- **ビットDP**：`dp[使った駅の集合][今いる駅]` ＝ 最長距離。関節点ごとの「そこから出る最長」「関節点どうしを結ぶ最長」の表を作ります。

### 4.2 フロンティアDP（細いブロック）

- 辺を1本ずつ「使う／使わない」と決めていきます。そのとき「すでに見たが、まだ未処理の辺が残っている駅」（フロンティア）について、未使用か、経路の途中か、部分経路の端か（端ならもう一方の端はどれか）だけを覚えます。
- 状態の数はフロンティアの幅だけで決まり、グラフの長さにはほぼ比例でしか効きません。辺の処理順は、幅が小さくなるもの（幅優先順と貪欲順を数通り試した中の最小）を選びます。
- 端のおまけ・端の固定（上の (3)）・ループの3種類に対応しているので、分枝限定法の3回の探索をそのまま置き換えられます。経路とループは別スレッドで同時に解きます。
- 幅8以上では、次の2つを加えます。
  - **上界による枝刈り**：「今の長さ＋未処理の辺でこの先稼げる上限」が最良解を超えない状態を捨てます。上限は、各駅が重い辺2本（端なら1本）の半分ずつを取る形と、ラグランジュ乗数で調整した最大全域森の形の2通りで計算し、小さい方を使います。
  - **ビームで基準を先に作る**：1ステップ1,000状態までに絞った同じDPを先に回して良い解を作り、それを基準に上の枝刈りをかけます。絞らない本番のDPで厳密性を保ちます。
- 幅12以下では、状態を64ビット1語で持つ版を使います（ハッシュや比較が軽くなるため）。
- 1ステップの状態が50万を超えたときは、ランクベース法（同じ形の状態の中から、線形代数で代表だけを残す方法。Bodlaender ほか 2013）で減らします。それでも1ステップ約100万、合計5,000万を超えたら諦めます。

### 4.3 分枝限定法

- 深さ優先で経路を伸ばします。経路の探索は始点ごと、ループの探索は「一番小さい番号の駅」を始点にして数えます。
- **上界**（これを超えられない枝は捨てる）：
  - 残りの駅のうち、到達できる部分だけを数える。関節点の先は、枝分かれのうち一番大きいものだけを数える
  - 各駅が重い辺2本の半分ずつを取る形
  - ラグランジュ緩和（全駅の「次数2以下」を罰金に移した最大全域森）。ループ用には辺を1本足した形
- **支配による枝刈り**：同じ「今いる駅・まだ行ける駅の集合」に、もっと長い距離で来たことがあれば捨てます。記録はスレッド間で共有します。
- **ラグランジュ分岐**：始点ごとに乗数を求め直します。それでも上界が落ちない始点は、少し探索して終わらなければ、最初の数歩（最大8歩）を決めて子ごとに乗数を求め直します。決めた道のりは長さ付きの仮想の辺1本にまとめるので、同じ探索をそのまま使えます。
- 探索の前に、初期解（貪欲法・最大全域木の直径・基本閉路・ビームサーチ・局所探索）で基準を作ります。駅は「重い辺の少ない順」に番号を付け直します（ループを一番小さい番号から数えるため、軽い駅から始めると早く打ち切れます）。

### 4.4 LP分枝カット法（太いブロック：密集・中くらいの密度）

- 経路を「仮想の駅 z を通るループ」と見なします。z は全駅と、その駅の端のおまけを重みとする辺で結ばれています。ループ問題として、辺と駅を0〜1の変数にした線形計画を解きます。
- 制約は「各駅の使う辺の数＝2×その駅を使うか」と、部分的な輪を禁止する制約です。後者は最小カット（Gomory-Hu 木）で、破られているものだけを順に追加します。
- 小数の解が出たら、その変数を0と1に分けて探索します。探索の順番は「上界が一番高いノードから」（最良優先）です。ただし、1に固定した側の上界が、残っているノードの最良の上界から0.05%以内なら、そのまま続けてそちらへ潜ります（潜り込み）。深さ優先だと、最初に選んだ枝が外れのときに、良い解が見つかるまでその枝の中を探し続けていました。
- 他のブロックとつながったブロックでも使います。そのときは、端のおまけと端の固定（2節の (1)〜(3)）を z の辺の重みと固定で表します。
- 部分的な輪の禁止に加えて、ブロッサム不等式（頂点の集合 H と、H から出る奇数本の辺 T について x(E(H)) + x(T) − Σ_H y ≤ (|T|−1)/2）を加えます。次数の式と上限から切り捨てで導ける形なので、どの H・T でも正しい制約です。
- 破られている制約は、違反の大きい順に1回20本まで加え、使われなくなった制約（余裕のある制約）は表から取り除いて、単体法の表を小さく保ちます。
- LPを使うときは、事前の初期解からビームサーチを外します（密集100駅で時間の96%を占めていたため）。LP自身が整数解を見つけていくので、軽い初期解で足ります。
- 単体法は自作の改訂単体法です（`revised.hpp`）。表 B^-1 A は持たず、元の疎な行列と基底の逆行列（積形式。入れ替え1回ごとに列ベクトル1本、64回ごとに作り直し）を持ちます。表を密に持つ版（`lp_bnc.hpp` の `BoundedSimplex`）は、照合用の独立した実装として残しています。
- 上下限付きの主・双対単体法です。ただし正しさは単体法に依存しません。
  - 枝を捨てる判断には、最終的な双対変数から計算した「どんな双対でも成り立つ形の上界」だけを使います。
  - 「解なし」の判断は、ファーカスの補題の形で検算できたときだけ採用します。
  - 見つけた解は、元のグラフで長さを測り直してから採用します。
  - 検算できない・反復が多すぎる・ノードが3,000を超える、のどれかなら諦め、分枝限定法に任せます。

## 5. 数値の扱い

- 入力の距離が全て「小数点以下6桁以内の普通の小数」なら、全距離を 10^d 倍して整数にします（例：8.54 → 854）。整数の和は 2^53 未満なら double でも誤差がありません。また、異なる答えの長さは最低でも1違うので、「より長い」は「0.5より大きく上回る」で判定します。合計が 2^50 以上になる場合は、この方法を使いません。
- 指数表記などそれ以外の形が1つでもあれば、浮動小数点のまま計算し、相対的な許容誤差で比べます。
- 整数化したのは、合計が大きいと0.01の差を見落とす不具合が見つかったためです。経緯は [HISTORY.md](HISTORY.md) の10節にあります。

### 5.1 どの環境でも同じ探索になるように

速さは探索の道筋で大きく変わるので、どのコンパイラ・標準ライブラリ・CPUでも同じ道筋をたどるようにしています。

- 乱数：`std::mt19937` の出力は規格で決まっていますが、`std::uniform_int_distribution` などの分布は実装ごとに違う値を返します。そこで、一様な整数・実数への変換は自前の式（`rand_int`、`rand01`）で行います。
- ハッシュ：`std::hash` も実装ごとに違うので、自前の混ぜ合わせ（splitmix64）を使います。
- 並べ替え：`std::sort` は同じ値どうしの順番が実装ごとに違うので、安定な並べ替え（`std::stable_sort`）か、番号で同点を決める比較を使います。
- 浮動小数点：融合積和（FMA）を使わない設定でビルドします（`-ffp-contract=off`、MSVC は `/fp:precise`）。ARM（Apple Silicon）でも計算結果が変わりません。
- 確かめ方：`bench/determinism.py` で、決まった入力を1スレッドで解いたときの統計（答え・各方法のノード数・LPのノード数・DPの状態数）を、Linux で記録した基準（`bench/results/determinism_ref.json`）と比べます。

## 6. メモリ確保

240バイト以下の確保は、プログラム専用の確保の仕組み（`src/alloc.hpp`）がスレッドごとの空きリストから取ります。小さい一時データを大量に作っては捨てる使い方に合わせたもので、普段の入力で約1割速くなります。`-DLP_NO_POOL` を付けてビルドすると、標準の malloc を使います。

## 7. 時間制限と並列化

- 時間制限は既定で無効です。有効にすると、各方法が定期的に時刻を確認します。error モードは何も出さずに終了コード2、approx モードはそれまでの最良の経路を出します。
- 時間切れのときは大きな記録表を解放せずに終了します（解放だけで約1秒かかったため）。制限の超過は0.03秒以内です。
- スレッドは、最大のブロックが40駅以上のときだけ使います（起動に約0.3ミリ秒かかり、小さいグラフでは速くならなかったため）。

## 8. 出力

- 経路の向きは「最初のID ≤ 最後のID」にそろえます。ループは一番小さいIDから始め、向きも決まった規則でそろえるので、同じ答えは毎回同じ形で出ます。
- 出力の前に、経路が実在する路線をたどっていること、駅の重複がないこと、長さが計算値と合うことを検算します。合わなければ何も出さず終了コード3で止まります。

## 9. 調整用の設定

通常は指定不要です。計測や照合で、ある方法を切ったり極端な条件にしたりするために使います。

| 指定 | 既定 | 意味 |
| --- | --- | --- |
| `--t-dp N` | 12 | ビットDP・列挙を使うブロックの最大駅数 |
| `--lagr-ratio R` | 1.3 | 初期解に対する上界の比がこれを超えたら、ラグランジュの上界を使わない |
| `--no-edge-deletion` | — | ラグランジュの上界で「使われ得ない」と分かった辺を消す処理を切る |
| `--x fdp=0` | 1 | フロンティアDPを使わない |
| `--x fdp_width=N` / `fdp_width_sparse=N` | 8 / 16 | フロンティアDPを使う幅の上限（通常／まばら） |
| `--x fdp_prune_width=N` / `fdp_beam=N` | 8 / 1000 | 枝刈りとビームを使い始める幅／ビームの幅 |
| `--x fdp_rank=N` | 500000 | ランクベース法を使い始める1ステップの状態数 |
| `--x lp_bnc=0` / `lp_max_n=N` / `lp_nodes=N` | 1 / 400 / 3000 | LP分枝カット法を使わない／使う最大駅数／諦めるノード数 |
| `--x lp_min_ratio10=N` | 10 | LPを使う最小の「辺の数÷駅の数」×10（20で以前の「密集だけ」の条件） |
| `--x lp_cuts_round=N` / `lp_light_init=0` | 20 / 1 | 1回に加える制約の数／LPの前のビームサーチを省かない |
| `--x lp_revised=0` / `fdp_lp_width=N` | 1 / 14 | 表を密に持つ単体法を使う／これより広いブロックはLPを先に使う |
| `--x lp_blossom=0` | 1 | ブロッサム不等式を使わない |
| `--x lp_order=0` / `lp_plunge_e4=N` | 1 / 5 | LPの探索を深さ優先にする／潜り込みを続ける幅（最良の上界に対する割合×10⁻⁴、0で潜り込まない） |
| `--x path_task=0` | 1 | 経路探索のラグランジュ分岐を使わない |
| `--x task_budget=N` / `task_depth=N` | 2000 / 8 | ラグランジュ分岐で、分ける前に試すノード数／分ける最大の深さ |
| `--x fdp_min_n=N` / `fdp_layer=N` / `fdp_budget=N` | 13 / 約100万 / 5,000万 | フロンティアDPを使う最小駅数／諦める1ステップの状態数／諦める合計状態数 |
| `--x enum_n=N` / `enum_budget=N` | 12 / 100000 | 全経路の列挙を使う最大駅数（0で使わない）／ビットDPに切り替える手数 |
| `--x par_min_block=N` | 40 | 複数スレッドを使う最大ブロックの駅数 |
| `--x exact_weights=0` | 1 | 距離を整数化しない（浮動小数点のまま） |
| `--x fdp_narrow=0` | 1 | フロンティアDPで1語の状態を使わない |
