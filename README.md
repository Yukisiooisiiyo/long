# 最長片道きっぷの旅（C++ 実装）

株式会社ドリーム・アーツ 2028年新卒エンジニア採用コーディングテストの解答です。

駅と路線の一覧を標準入力から読み、同じ駅を2回通らずに距離の合計が最大になる経路を標準出力に出します。始点と終点は自由で、同じ駅でも構いません（ループ）。

- **既定では必ず厳密解（最長）を返します。** 近似解は、時間制限を有効にして「近似モード」を選んだときだけ出します。
- 外部ライブラリは使っていません（C++20 の標準ライブラリだけ）。
- 想定した入力の種類（鉄道網に似た形・格子・密集・小さいループの連なり）で、規模を変えて計測と照合をしています。

## ビルド

C++20 のコンパイラが必要です（GCC 10 以降、Clang 13 以降、Apple Clang 14 以降、Visual Studio 2019 16.10 以降）。

**CMake（Windows・Mac・Linux 共通）**

```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

実行ファイルは `build/longest`（Visual Studio では `build\Release\longest.exe`）にできます。Linux と Windows では標準ライブラリを埋め込む静的リンクが既定です（起動が約1ミリ秒速くなるため）。Mac は完全な静的リンクができないので対象外です。切るときは `-DLONGEST_STATIC=OFF` を付けます。

**CMake を使わない場合**

```
g++ -std=c++20 -O3 -pthread -static -o longest src/main.cpp     # Linux（clang++ も可）
clang++ -std=c++20 -O3 -pthread -o longest src/main.cpp         # Mac
cl /std:c++20 /O2 /EHsc /utf-8 src\main.cpp /Fe:longest.exe     # Windows（Developer Command Prompt for VS）
```

動作確認済みの環境：Linux x86_64（GCC 13.3、CMake 3.28）。Windows・Mac は上の手順を想定していますが、実機では未確認です。

## 使い方

```
longest < input.txt
```

入力例（問題文の例）と出力：

```
1, 2, 8.54          1
2, 3, 3.11    →     2
3, 1, 2.19          3
3, 4, 4             4
4, 1, 1.4           1        （長さ 17.05 のループ）
```

- **入力**：`始点ID, 終点ID, 距離` を1行ずつ。数値の前後の空白、CRLF / LF、空行、最終行の改行なしに対応します。同じ区間が2回あれば長い方、始点と終点が同じ行は無視します。
- **出力**：経路の駅IDを1行ずつ、改行は CRLF（最後の行の後にも付けます）。ループのときは最後に始点IDをもう一度出します。標準出力にはこれ以外を一切出しません。
- 同じ長さの経路が複数あるときは、そのうち1つを出します（向きは「最初のID ≤ 最後のID」にそろえます）。

| オプション | 既定 | 意味 |
| --- | --- | --- |
| `--time-limit true\|false` | false | 時間制限を有効にする |
| `--time-limit-sec S` | 10 | 制限時間（秒） |
| `--on-timeout error\|approx` | error | 時間切れのとき：error＝何も出さず終了コード2、approx＝それまでの最良の経路を出す（最長とは限らない） |
| `--threads N` | 自動 | スレッド数。指定しないときは CPU のコア数（ただし小さいグラフは1スレッド） |
| `--verbose` | なし | 標準エラーに統計を出す（標準出力は変わらない） |
| `--t-dp N` / `--lagr-ratio R` / `--no-edge-deletion` / `--x 名前=値` | — | 調整・検証用（[docs/DESIGN.md](docs/DESIGN.md) の「調整用の設定」） |

終了コード：0 正常、1 入力または引数のエラー、2 時間切れ（error モード）、3 内部エラー（出力前の自己検証で不整合を検出）。

## 解き方の概要

最長経路問題は NP 困難で、どんな入力でも速い方法は知られていません。そこで、入力を性質の違う部分に分け、部分ごとに一番合う厳密な方法を選びます。

```
入力 → 連結成分 → ブロック（1駅では切り離せない部分）に分解
          │
          ├─ ループだけのブロック ……………… 公式（2つの弧のどちらか）
          ├─ 小さいブロック（12駅以下） …… 全経路の列挙 か ビットDP
          ├─ 細いブロック（幅14以下） ……… フロンティアDP（＋上界による枝刈り）
          ├─ それ以外（密集・中くらいの密度・広い格子） … LP分枝カット法（自作の改訂単体法）
          └─ 上の方法が諦めたとき ……………… 分枝限定法（ラグランジュ緩和の上界）
          ↓
ブロックの結果を木構造の上でつなぐ（関節点の先で稼げる距離を「端のおまけ」として渡す）
          ↓
最長の経路とループのうち長い方を出力
```

どの方法も厳密で、近似で打ち切ることはありません（時間制限の近似モードを除く）。方法ごとの詳しい中身と、どれを使うかの条件は [docs/DESIGN.md](docs/DESIGN.md) にあります。

## 正しさの確かめ方

```
python3 tests/check.py ./longest prototype_python 300 1                  # 総当たり（10駅以下）・Python試作と照合
REF_BIN=<別の版> python3 tests/check_fdp.py ./longest prototype_python 200 1  # 解き方ごとの極端な設定を総当たり・別の版と照合
python3 tests/check_big.py ./longest <別の版>                             # 大きい入力を独立した方法と照合
python3 tests/check_precision.py ./longest 400 1                         # 大きな値・桁数の混在を有理数の総当たりと照合
```

- 小さい入力は総当たりと、中くらいの入力は独立に書いた Python 試作（`prototype_python/`、設計段階の対照実験に使ったもの）と照合しています。
- 解き方ごとに「その方法を全部のブロックに強制する」「わざと途中で諦めさせる」などの極端な設定を含めて照合しています。
- 照合の総数は数万回で、不一致は0件です（内訳は [docs/BENCHMARKS.md](docs/BENCHMARKS.md)）。
- 距離が普通の小数（小数6桁以内）なら整数にして計算するので、合計がどれだけ大きくても0.01の差を取りこぼしません。
- 実行時にも、出力する前に経路が実在する路線をたどっていることと長さを検算し、合わなければ終了コード3で止まります。

## 速さ

Linux x86_64（2コア）での実測です。プロセスの起動を含み、各規模とも3パターンの最悪値です。

| 入力 | 駅数 | 時間 |
| --- | --- | --- |
| 問題文の例 | 4 | 0.0012秒（ほぼ起動時間） |
| 鉄道網に似た形 | 1,000 / 5,000 | 0.023秒 / 0.055秒 |
| 小さいループの連なり | 100,000 | 0.27秒 |
| 格子 | 10×10 / 13×13 | 0.049秒 / 2.0秒 |
| 格子 | 14×14 / 16×16 | 2.8秒 / 2.7秒（3つ中2つ。残る1つは27秒） |
| 密集（駅の約半分どうしが直結） | 80 / 200 | 0.036秒 / 1.1秒 |
| 各駅3〜5本のランダムなグラフ | 100 / 200 | 0.28秒 / 1.7秒 |

苦手な入力：格子20×20は30秒以内に終わりません。格子16×16にも27秒かかるものがあります。全データと再現方法は [docs/BENCHMARKS.md](docs/BENCHMARKS.md) にあります。

## ファイル構成

```
src/main.cpp        入出力・オプション・時間制限・出力前の検算
src/graph.hpp       グラフ、入力の読み込み、連結成分・ブロック分解
src/solver.hpp      全体の流れ（ブロックごとの方法選択と結果の合成）
src/bitdp.hpp       小さいブロック：ループの公式・全経路の列挙・ビットDP
src/frontier.hpp    細いブロック：フロンティアDP
src/lp_bnc.hpp      太いブロック（密集・中くらいの密度・広い格子）：LP分枝カット法
src/revised.hpp     LP分枝カット法で使う改訂単体法
src/search.hpp      分枝限定法
src/lagrange.hpp    ラグランジュ緩和の上界
src/heuristics.hpp  初期解（上界と比べる基準）
src/alloc.hpp       小さいメモリ確保を速くする専用の仕組み
tests/              照合テスト
bench/              計測スクリプト・入力データ・計測結果
docs/DESIGN.md      解き方の詳細と、方法を選ぶ条件
docs/HISTORY.md     どういう考えで今の形に決めてきたかの記録
docs/BENCHMARKS.md  計測・照合の全データ
prototype_python/   Python 試作（照合テストの参照解と、計測用の入力の生成器）
```
